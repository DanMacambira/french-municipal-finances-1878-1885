# Experimental extraordinary-tax OCR (1882, PDF p.245)

This experiment deliberately does **not** modify the main extraction, parser, page ranges, original OCR JSON, or commune-year dataset.

## Why

The printed tables store extraordinary-centime rates and expiry years as vertically stacked pairs, sometimes grouped by braces. Mistral's full-table HTML occasionally detaches these entries from their commune rows. A complementary pass may help recover *vertical alignment* between commune labels and tax entries; the outcome must be tested against the scans.

## What changes

Adds `code/tax_ocr_pilot.py`, calibrated **only** for two problematic panels of the 1882 PDF page 245: `left_col2` and `right_col2`. Using existing 210 dpi rendered panel images, it places a commune-name strip and a centimes/expiry-year strip side by side **without shifting their vertical coordinates**. Both remain unmodified copies of original pixels. The omitted financial columns are not needed for this specific test.

## Run the experiment

From the repository root (the required panel images were generated by the prior `make preview --regions`):

```sh
.venv/bin/python code/tax_ocr_pilot.py preview
```

Inspect the two PNGs under `derived/situation_financiere/tax_ocr_pilot/images/1882/`. Ensure that names, centimes and expiry years are fully visible. This step is free.

Only after visual inspection, with a valid `MISTRAL_API_KEY` set in the current terminal:

```sh
.venv/bin/python code/tax_ocr_pilot.py ocr --yes
```

The pilot submits **at most two images** to the same Mistral OCR endpoint already used in the main pipeline and caches the raw results under `derived/situation_financiere/tax_ocr_pilot/ocr/mistral/1882/`. Re-running unchanged images hits the cache. `--force` reissues paid calls, so do not use it casually.

Compare the two new JSON responses with the original `p0245_left_col2.json` and `p0245_right_col2.json` and the scans, assessing the number of pairs recovered and how accurately each pair is attributed to its commune. The tax-only results are **not automatically merged** into `make build`. A geometry-based attribution and correction layer should be designed after we have the evaluation result.

Crop fractions in `PRESETS` are **specific to the reviewed pilot images**; do not reuse on other pages without calibration.

This procedure uses the ordinary OCR API, **not** schema-guided annotations or fine-tuning. It avoids reliance on an unverified model endpoint. Prices and quotas must be checked with the provider before scaling beyond the pilot.
