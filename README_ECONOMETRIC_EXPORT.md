# Pas-de-Calais: general-purpose econometric export (1878–1885 pilot)

This add-on runs **after** the existing OCR `build`. It does not re-run Mistral and makes **zero API requests**. It is intentionally generic: no PDF page numbers, exception lists, image-name overrides, or OCR guesses are hard-coded. The CLI and output layout can be reused for later departments and 1886–1900, once their printed headings have been reviewed and the main extraction workflow expanded.

## Rationale

From the scanned 24-panel sample, the printed 1878–1885 Pas-de-Calais pages have the same **nine-column** header: commune; population; hectares; annual revenues; value of centime; total centimes; extraordinary centimes; extraordinary-tax expiry year; charity-bureau revenue. This add-on offers an *opt-in* 9-column mapping across these years, not a claim that every broken OCR HTML table has nine intact columns. Existing year-specific mappings (including 1882's reviewed eight-column exception) are left untouched. Other incomplete widths stay unmapped/flagged until reviewed. Do **not** automatically apply this mapping to 1886–1900 or other departments without visually checking their headings.

## Files in the ZIP

- `tools/install_shared_layout.py` — safe, opt-in augmentation of your existing `column_mappings.json`; backs up your file.
- `code/export_econometric_panel.py` — reads the candidate CSV generated by `build` and produces a consistent long commune–year panel, plus review/exclusion files.
- `tests/test_export.py` — offline regression tests.
- `README_ECONOMETRIC_EXPORT.md` — these instructions.

## Installation

Unzip the ZIP into the **main GitHub project** root (`~/dev/french-municipal-finances-1878-1885/`), **not** into `~/dev/ocr_benchmark/`. Do not replace the existing `situation_financiere.py`, `column_mappings.json`, or your OCR caches. The ZIP contains only new files. Activate the **main project's** environment and install its requirements if needed.

```bash
cd ~/dev/french-municipal-finances-1878-1885
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p 'test_export.py' -v
```

## Step 1: Register the common printed layout (no API calls)

```bash
python tools/install_shared_layout.py --repo .
# Read the dry-run summary; then:
python tools/install_shared_layout.py --repo . --apply
```

This step adds one generic 9-column mapping for 1878–1881 and 1883–1885 (unless you have already added one); 1882's current 9- and 8-column mappings are retained. No per-page corrections are inserted. This creates a timestamped backup in `schema/situation_financiere/`—leave that backup uncommitted or move it outside the repo.

**Caution:** It is still worth checking all year-specific heading variations before publishing; an OCR output with 9 columns is not proof of correct alignment.

## Step 2: Build the candidates from your local OCR caches (no API calls)

Your existing matcher requires the local historical commune reference workbook and the `communematch` dependency. If it is not installed, resolve that first. Do **not** use `--no-match` for a final matched panel.

```bash
python code/situation_financiere.py build
```

If your OCR is still only cached for pilot pages, the export will contain **only those pages**. Missing page coverage must be addressed before treating the output as a complete 1878–1885 panel. Verify all needed panels exist first.

## Step 3: Produce the export (no API calls)

```bash
python code/export_econometric_panel.py --repo .
```

The generated files are saved under the **gitignored** folder `derived/situation_financiere/econometric_export/`:

- **`commune_year_panel_provisional.csv` / `.parquet`** — long panel, one row per **unique matched** `(year, cassini_id)`. Includes OCR quality flags; potentially incomplete observations are retained. This is the starting point for econometric work.
- `commune_year_panel_strict.csv` / `.parquet` — subset with all five main financial/demographic variables present and no core review flags; still **not** manually verified.
- `commune_year_candidates.csv` / `.parquet` — *all* candidates, with IDs, source panels, review flags and typed variables, including duplicate/unmatched observations.
- `excluded_unmatched.csv` and `excluded_duplicate_ids.csv` — exclusions that must be resolved before a comprehensive panel is claimed. No duplicate is silently chosen.
- `review_queue_core.csv` — review priorities for the main variables, not dominated by extraordinary-tax warnings.
- `extraordinary_taxes_unverified.csv` — preserved but excluded from the main research panel.
- `year_quality_summary.csv` — coverage/duplicates/missingness by year.
- `export_report.json` — provenance and summary.

**Variables**: `year`, `cassini_id`, `commune_name`, `population`, `superficie_hectares`, `revenus_annuels_francs`, `valeur_centime_francs`, `centimes_total`, and the optional `revenus_bureau_bienfaisance_francs` (converted from the original raw OCR field only when unambiguous), plus canton/arrondissement and source metadata. Raw exceptional-tax fields are in a separate file.

The panel **does not** fill missing values with zero, infer missing commune IDs, guess missing digits, or pick one of two duplicate records. OCR-derived fields retain `source_status = "ocr_unverified"` unless your source declares otherwise. Missingness, manual uncertainty, and unmatched observations remain inspectable.

## Next checks before running regressions

1. Confirm all intended printed pages and both table panels were extracted; compare coverage to the source inventory and expected commune counts. A large number of matched rows is not the same as complete coverage.
2. Inspect `year_quality_summary.csv`, `excluded_duplicate_ids.csv`, and `review_queue_core.csv`; resolve obvious extraction/matching failures.
3. Inspect `commune_year_panel_provisional.csv` and compare a small random selection of core numeric cells to scans (the prior 96-row exercise is not an independent double transcription).
4. Check whether `cassini_id` is stable for commune mergers, splits and historical names across time; never assume geographic boundaries are constant without evidence.
5. Only after those checks, decide on analysis-specific sample restrictions (e.g. balanced panel). **Do not** enforce a balanced panel in the extraction pipeline.

## Scale-up to 1878–1900 / all departments

The exporter is department/year neutral **once** the input has stable geographic IDs and reviewed column mappings. The *upstream* extractor is not yet universal: at present it has a fixed 1878–1885 list and Pas-de-Calais page selection. Before nationwide scaling, replace year-only input identifiers with `(department, year, source_page, panel)`, maintain departmental layout metadata, and identify each commune with a stable ID. Do not solve that by growing page-number exception lists.
